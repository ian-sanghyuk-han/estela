# 자동 갱신 — 명부는 살아 있고 우리 사본은 굳어 간다

식당은 매일 열고 닫는다. 우리가 8월에 받아 둔 사본은 8월의 세상이고, 그대로 두면
「영업 중」이라고 적힌 채 문 닫은 집이 쌓인다. 명부 24개와 Overture를 **스스로**
다시 받아야 한다.

## 무엇이 있고 무엇이 없나 (2026-09-10)

| | 곳 | 다시 받는 코드 |
|---|---|---|
| 한국 5종 | 867,648 | **있음** — `tools/harvest_korea.py` |
| Overture 216나라 | 8,983,886 | **있음** — `tools/harvest_overture.py` |
| 나머지 정부 명부 19종 | 488,762 | **없음** — 임시 폴더가 지워질 때 같이 사라졌다 |

19종은 영국 FHRS, 프랑스 둘, 덴마크, 홍콩, 토론토, 멜버른, 미국 12곳이다. 자동 갱신을
말하려면 이것부터 다시 써야 한다. 그래서 순서는 **① 잃어버린 채취기 복원 →
② 어디서 돌릴지 → ③ 일정**이다.

## ① 되살릴 것 — 받는 길이 명부마다 다르다

| 출처 | 받는 길 | 조심할 것 |
|---|---|---|
| 🇬🇧 uk-fhrs | FSA 열린 자료 XML, 지자체별 파일 | 위생 등급은 싣지 않는다 |
| 🇫🇷 fr-alim · fr-bouche | Alim'confiance 전국 CSV 한 장 | 위생 판정은 싣지 않는다 |
| 🇩🇰 dk-smiley | Fødevarestyrelsen Smiley XML | 스마일리 등급은 싣지 않는다. 좌표 없는 줄이 남아 있다 |
| 🇭🇰 hk-fehd | FEHD 일일 XML | **좌표가 없다** — ALS 주소 조회로 채운다 |
| 🇨🇦 ca-toronto | CKAN DineSafe | 업종 칸이 없어 식료품점이 섞인다 |
| 🇦🇺 au-melbourne | 시 사업체 총조사 | 면허 대장이 아니다. 최신 연도만 |
| 🇺🇸 12곳 | Socrata (도시마다 다른 도메인·자료 번호) | 지오코딩이 틀린 줄이 있다 |

**남의 지오코딩을 믿지 마라.** 처음 받았을 때 댈러스는 21.8%가 댈러스 밖(하와이·알래스카)
이었고, 뉴욕주는 경도 −778을 냈고, 새너제이는 좌표 한 쌍이 뒤집혀 터키로 갔다. 그래서
출처마다 관할 구역 네모를 두고 그 밖으로 나간 줄을 버린다. 이 검사는 채취기와 한 몸이라
같이 되살려야 한다.

## ② 어디서 돌릴 것인가

**GitHub Actions.** 선장님 PC가 늘 켜져 있지 않으므로 «자동»이 되려면 남의 기계여야 한다.
공개 저장소는 무료다. 한 작업 6시간, 디스크 14GB가 한계라, Overture는 대륙별로 갈라
여러 작업으로 돌린다. 정부 명부 19종은 다 합쳐도 몇 분이면 된다.

## ③ 여기 함정이 하나 있다 — 저장소가 부푼다

깃은 **옛 판을 지우지 않는다.** 지금도 785MB 자료의 역사가 361MB, 584MB 색인의 역사가
250MB다. 달마다 새로 올리면 Overture 이름이 조금씩 바뀌면서 칸 파일 7만 8천 개가 거의
다 새 파일이 되고, 한 번에 300MB 남짓이 역사에 쌓인다. **1년이면 4GB다.**

그래서 자료 저장소와 색인 저장소는 **역사를 남기지 않는다.** 갱신할 때마다 뿌리 없는
커밋 하나로 갈아엎는다(`tools/publish.py`). 잃는 것은 «지난달 판으로 되돌리기»인데,
그건 도구와 원본이 있으면 다시 만들 수 있다. 얻는 것은 저장소가 영영 한 판 크기로
머무는 것이다. **앱 저장소(`estela`)는 그대로 역사를 쌓는다** — 거기가 진짜 작업이다.
